Every run of the JW Enjoy Life Scraper follows the same linear pipeline: read your configuration, scrape HTML pages for API links, resolve those links to video metadata JSON, ask a few questions about what and how you want to download, then stream every video to disk. The sections below trace each step in order so you know exactly what to expect — and where to look if something goes wrong.

## Full Run Walkthrough

<Steps>

  <Step title="Banner and welcome message">
    The CLI opens by rendering an ASCII art banner via Figlet — "JW Scraper" — followed by a bold welcome line:

    ```text
    ____  ____  _____  ____  ____  __   ____  ____  ____  ____
    ...  (Figlet art) ...

    Welcome to the Enjoy life Scrapper. A CLI that scrapes JW.ORG and gets
    enjoy life videos to download in bulk
    ```

    No user input is required at this stage.
  </Step>

  <Step title="Load config.json">
    The scraper calls `ConfigurationService.GetConfig("config.json")`, which reads and deserializes the file from the current working directory into a `Dictionary<string, Dictionary<string, string>>`.

    - The **outer key** is the language name (e.g. `"English"`, `"Spanish"`).
    - The **inner key-value pairs** map section names to their JW.ORG HTML page URLs.

    If the file is missing or cannot be parsed, the program logs a bold error — `No Config File Found` — and exits immediately.

    ```json
    {
      "English": {
        "Unit 1": "https://www.jw.org/en/library/videos/#en/mediaitems/...",
        "Unit 2": "https://www.jw.org/en/library/videos/#en/mediaitems/..."
      },
      "Spanish": {
        "Unit 1": "https://www.jw.org/es/biblioteca/videos/#es/mediaitems/..."
      }
    }
    ```

    <Note>
      `config.json` must live in the directory from which you run the binary. The path is resolved relative to the process working directory, not the executable location.
    </Note>
  </Step>

  <Step title="Select a language">
    The CLI presents an interactive prompt populated with every top-level key found in `config.json`:

    ```text
    Select The Language:
    > English
      Spanish
    ```

    The selection determines which `Dictionary<string, string>` of section URLs is used for all subsequent stages.
  </Step>

  <Step title="Stage 1 — HTML scraping">
    The scraper calls `WebScraper.ScrapeJsonUrlsFromSections(sectionUrls)`, which iterates every section URL and performs the following steps per URL:

    1. `CacheService.GetText(url)` fetches the HTML page (or returns a cached `.txt` copy from the `.cache` directory if it was fetched before).
    2. The raw HTML is loaded into an `HtmlDocument` via **HtmlAgilityPack**.
    3. The following XPath is executed against the document:

    ```text
    //div[contains(@class, 'du-margin-children-vertical-desktopOnly--0')]
    ```

    4. Each matched `<div>` is inspected for a child `<div>` whose `data-jsonurl` attribute holds the JW media API endpoint for that publication.
    5. The extracted URLs are cached in memory (keyed by a SHA-256 hash of the HTML text) so repeated runs skip re-parsing.

    A live progress bar labelled **"HTML Progress:"** updates as each section completes.

    <Note>
      All three pipeline stages share the same `ParallelOptions` instance, which sets `MaxDegreeOfParallelism = 8`. Up to eight network operations run concurrently at any time across all stages.
    </Note>
  </Step>

  <Step title="Stage 2 — JSON scraping">
    `WebScraper.ScrapeJsonResponseFromUrls(jsonUrls)` calls `CacheService.GetJson<JsonResponse>()` for each API URL discovered in Stage 1 **in parallel**, retrieving structured video metadata for every publication.

    - URLs within each section are fetched concurrently via `ParallelHelper` (`Parallel.ForEachAsync`); sections themselves are processed sequentially so progress tracking remains accurate.
    - Responses are cached as `.json` files under `.cache/` so they are not re-fetched on subsequent runs.
    - Each `JsonResponse` contains publication details and a `Files` dictionary whose values hold `FileDetail` objects listing every available `MovieDetail` (one per resolution).

    A **"JSON Progress:"** bar tracks completion across all sections in aggregate.
  </Step>

  <Step title="Select a section">
    After both scraping stages complete, the CLI prompts you to narrow the download scope:

    ```text
    Select the Section To be Downloaded:
    > All
      Unit 1
      Unit 2
      Unit 3
    ```

    Choosing **All** passes every section to the download stage. Choosing a specific section filters the response map to that single key.
  </Step>

  <Step title="Select a resolution">
    `Helper.GenerateMetadata()` sums `MovieDetail.FileSize` for every video at each resolution label, then `Helper.FormatFileSize()` converts the byte total into a human-readable string (e.g. `1.23 GB`). The prompt displays size estimates alongside each option:

    ```text
    Select The Resolution:
    > 240p: 1.23 GB
      360p: 2.45 GB
      480p: 3.78 GB
      720p: 6.12 GB
      3gp: 512.00 MB
    ```

    The scraper records the selected label string and uses it to filter `MovieDetail` records during download.
  </Step>

  <Step title="Set the target directory">
    ```text
    What is the directory to store the files(empty is the current directory)?
    ```

    - If the path you enter exists on disk, it is used as-is.
    - If the input is empty or the path does not exist, files are saved to `files/` inside the current working directory (`Path.Combine(Directory.GetCurrentDirectory(), "files")`).
  </Step>

  <Step title="Select a file name type">
    ```text
    Select The File Name Type:
    > JW Library Style (Difficult to Read File Name)
      Simple (Easy to Read File Name)
    ```

    - **JW Library** (`DownloadFileNameType.JwLibrary`): uses the server-side filename extracted from `Path.GetFileName(uri.AbsolutePath)`, e.g. `jwb-080_E_eljj_01_r240P.mp4`.
    - **Simple** (`DownloadFileNameType.Simple`): uses `MovieDetail.Title + Path.GetExtension(urlPath)`, e.g. `Let Us Learn to Worship Jehovah.mp4`.

    See [File Organization](/guides/file-organization) for the full breakdown.
  </Step>

  <Step title="Select a file path type">
    ```text
    Select The File Path Type:
    > JW Library Style (Videos divided by Section [config])
      Simple (All Videos in one Directory)
    ```

    - **Grouped** (`DownloadFilePathType.Grouped`): creates a sub-directory per config section key, e.g. `files/Unit 1/`.
    - **Simple** (`DownloadFilePathType.Simple`): places all videos directly in the target directory.
  </Step>

  <Step title="Stage 3 — Downloading">
    `WebScraper.DownloadAllFiles()` iterates each section's list of `JsonResponse` objects. For each response it navigates `Files.Values.FirstOrDefault()?.MovieMp4S`, filters to the `MovieDetail` where `Label == resolution`, and calls `CacheService.Download()` to stream that video to disk.

    - `CacheService.Download()` checks whether a file already exists **and** has the expected byte length (`FileInfo.Exists && FileInfo.Length == fileSize`). If both conditions are true, the file is skipped entirely.
    - Otherwise the video is streamed from the URL via `HttpClient.DownloadStream()` and written to disk with `FileStream.CopyToAsync()`.
    - Filenames are sanitised with `Helper.SanitizeFileName()` before the path is constructed.

    A **"Download Progress:"** bar updates after each video completes, regardless of whether it was skipped or freshly downloaded. Individual download errors are logged but do not abort the remaining queue.
  </Step>

</Steps>

## Parallelism and Resilience

<CardGroup cols={2}>
  <Card title="Parallel execution" icon="bolt">
    All three stages use `Parallel.ForEachAsync` with `MaxDegreeOfParallelism = 8`, meaning up to eight network operations run concurrently at any time.
  </Card>
  <Card title="Error isolation" icon="shield">
    Each stage wraps every item in a `try/catch`. An error on one URL or video is logged at `ILogger.Level.Error` and the remaining items continue processing normally.
  </Card>
  <Card title="HTTP and HTML caching" icon="database">
    HTML pages are cached as `.txt` files and API responses as `.json` files under `.cache/`. Parsed HTML results are also cached in-memory by SHA-256 hash.
  </Card>
  <Card title="Download resumption" icon="rotate-right">
    Downloads are skipped when `FileInfo.Exists && FileInfo.Length == fileSize`, providing byte-exact resume behaviour without any extra bookkeeping.
  </Card>
</CardGroup>

<Tip>
  If a run is interrupted mid-download, simply re-run the scraper from the same working directory with identical settings. The `.cache/` directory preserves all fetched HTML and JSON, and any fully downloaded video files are detected by their byte length and skipped automatically — only incomplete or missing files are re-downloaded.
</Tip>
